# مَآب — Phase 1: Prayer Countdown Correction

التاريخ: 2026-09-29
النطاق: تصحيح حساب العدّ التنازلي للصلاة التالية فقط، مع الحفاظ الكامل على المحتوى التجريبي وواجهة العرض.

> **تنويه:** أوقات الصلاة التجريبية، الموقع الثابت («الرياض، المملكة العربية السعودية»)، وتقدّم القرآن النموذجي **محفوظة عمدًا** لمرحلة تطوير الواجهة. لم تُستبدل بحالات «غير متاح» أو شرطات أو شارات تجريبية. ربط بيانات حقيقية (حساب فلكي / أذونات موقع / API / جدولة الأذان / وظيفة القرآن) أو حالة «غير متاح» صادقة **متطلب لإصدار عام لاحق، خارج نطاق هذه المرحلة**.

---

## 1. العيب المؤكد وتصحيحه

### التشخيص (مؤكد على الكود الحالي، لا على افتراض التدقيق)

في `PrayerSchedule._statusFor` (`lib/features/home/domain/prayer_schedule.dart`)،
عندما يكون الوقت الحالي **قبل** فجر اليوم (`last == null`)، كان الكود يستهدف
`_tomorrowFajr(item)` — أي فجر الغد:

```
قبل الإصلاح (04:00، فجر اليوم 04:50):
  status = upcoming(fajr, غدًا 04:50)
  duration = 24h 50m  ← خطأ («٢٤ ساعات و٥٠ دقيقة»)
بعد الإصلاح:
  status = upcoming(fajr, اليوم 04:50)
  duration = 50m      ← صحيح («٥٠ دقيقة»)
```

### الإصلاح

تغيير سطر واحد منطقيًا داخل `_statusFor`: قبل صلاة اليوم الأولى يكون الهدف هو
**فجر اليوم نفسه**؛ حالة «بعد العشاء» (الفجر التالي) تُعالج في الفرع الختامي
الموجود أصلًا والذي يبني `_tomorrowFajr` من فجر اليوم. لم يُقمَم أي مدة زمنية
خاطئة ولم يُغيَّر نص العرض فقط — قُحّح الاختيار نفسه.

**التقنية المستخدمة:** `DateTime` مؤرّخة كاملة محليًا
(`DateTime(y, m, d, hh, mm)` عبر `LocalDay.date`)، والانتقال بين الشهور/السنوات
يُشتق عبر `Duration(days: 1)` على الوقت المؤرّخ، فيتعامل Dart مع طول الشهر
وسنة الكبس تلقائيًا (مغطّى باختبارَي 30 سبتمبر ← 1 أكتوبر و31 ديسمبر ← 1 يناير).

### اتفاقية اللحظة الحدّية (exact-time boundary)

| الوقت الحالي | السلوك |
|---|---|
| قبل فجر اليوم | عدّ تنازلي إلى **فجر اليوم** |
| عند لحظة الصلاة بالضبط | تلك الصلاة «حان الآن» بمدة صفر (`ongoing`, `Duration.zero`) |
| بعد لحظتها حتى نهاية نافذة 30 دقيقة | «حان الآن» مستمرة |
| بعد النافذة حتى ساعة | «مرّ على …» (`passed`) |
| بعد الساعة وقبل الصلاة التالية | عدّ تنازلي إلى التالية (`upcoming`) |
| بعد عشاء اليوم (بعد ساعة «مرّ») | عدّ تنازلي إلى **فجر الغد** (يعبر الشهر/السنة) |

هذه نوافذ العرض (`prayerWindow = 30min`, `recentlyPassed = 1h`) **سلوك قائم
مسبقًا وحُفظ دون تغيير** — نطاق Phase 1 هو صحة الاختيار الزمني فقط.

### انحراف موثق: الاقتران بين العرض والاختيار

نوافذ «حان الآن» و«مرّ» **ليست منفصلة** عن اختيار الصلاة التالية الزمني:
كلاهما داخل حلقة واحدة في `_statusFor`، حيث تعمل نوافذ العرض كبوابات: إذا
وقع `now` داخل نافذة صلاة ما فلا يُحسب «التالي» إطلاقًا في تلك اللحظة — يعود
السطر بـ`ongoing`/`passed` بدلًا من `upcoming`. مثال: بعد فجر بثانية واحدة
يعيد `_statusFor`:

```dart
PrayerStatus(kind: PrayerStatusKind.ongoing, prayer: fajr)  // duration = 0
```

وليس «باقي على الشروق …». أي أن السطر الواحد يجيب عن سؤالين: «ما العرض
المناسب الآن؟» و«ما الصلاة التالية زمنيًا؟» — ولم تُطلب قيم الشروق/الظهر
إلا بعد انقضاء النوافذ. هذا **انحراف صريح عن قاعدة الحدود المطلوبة** (التي
تفصل الاختيار الزمني عن العرض)؛ حُفظ كما هو بهذه الجلسة التوضيحية دون
إعادة تصميم، وأي فصل مستقبلي (مثل إرجاع «الصلاة التالية» و«حالة العرض»
كقيمتين مستقلتين) قرار تصميمي لمرحلة لاحقة.

## 5. القيود الموثقة

1. **جدول تجريبي متكرر:** `PrayerSchedule` يبني الأوقات من `TimeOfDayish` ثابتة
   (نفس الأوقات كل يوم). لا يدعم التجريد جدولًا مختلفًا لكل تاريخ، لذا «فجر
   الغد» بعد العشاء يستخدم **قيم الجدول التجريبي نفسها** — وهو السلوك المحفوظ
   عمدًا في هذه المرحلة. عند ربط مزوّد أوقات حقيقي يجب أن تُبنى `timesFor`
   لكل تاريخ على حدة (الـAPI الحالي `timesFor(DateTime day)` جاهز لذلك).
2. **خلل عرض قديم محفوظ (خارج النطاق):** المُنسّق `formatDuration` يسبق صيغة
   المثنى برقمها («٢ ساعتين» بدل «ساعتين») — سلوك قائم قبل هذه المرحلة.
   الاختبار الذي يثبّت هذا الناتج **اختبار توصيف لخلل معروف (characterization)**
   وليس قبولًا بسلامة التنسيق؛ أي إصلاح مستقبلي له تغيير واعٍ ومقصود.
3. **التحقق على الجهاز:** **NOT RUN** — لا يوجد جهاز/محاكي Android متاح
   (`flutter devices`: Windows وChrome وEdge فقط). خطوات التحقق اليدوي عند
   توفر جهاز: تشغيل التطبيق قبل 04:50 محليًا والتأكد أن السطر يعرض «باقي على
   الفجر ٥٠ دقيقة» (وليس ٢٤ ساعة) مع بقاء بقية العرض كما هو.
4. لم يُدَّعَ أي تحسن أداء أو تحقق بصري دون دليل — لا قياسات ولا لقطات في هذه
   المرحلة.

الحقيقية لإصدار عام لاحق.
